Codex Desk Companion LILYGO T-Display-S3 · 320×170 · USB

A small thing on your desk that knows when your agent needs you.

It watches your Codex session and shows it as a face. Mostly it sits there calmly. When your agent is waiting on a decision, you know from across the room.

Plug it into any USB port or charger and it works. There is no app, no account, no pairing, and no network of any kind. The software further down this page is a bonus you can ignore forever.

The two buttons carry the rest of it with nothing attached: a do-not-disturb sign, the day's counters, a pomodoro, and a game to play through a long turn.

The five states

The face is the whole interface. Each state has an expression, and the ring beneath it carries the number when a host is connected. Nothing here needs reading, which is the point: you catch it in peripheral vision while you are doing something else.

These five are what a host drives. With nothing on the other end of the cable, or after five minutes of silence from something that was there, it runs an ambient screen of its own instead, so a board on a desk with no software never sits looking asleep or broken.

The first time you plug it in

A brand new board plays this once, then never again. The flag that arms it lives in a region of flash that reflashing does not touch, so every unit can be built, tested and powered a dozen times and still owe its owner the whole thing.

It is a creature waking up, not a device starting. It takes about nine seconds, it says three things (Hi OpenAI, your name, hello), and it needs no software to happen.

The optional program

If you want the device to follow your actual Codex session, there is one command. npm fetches the repository, caches it under ~/.npm/_npx and runs it from there. Nothing goes on your PATH, nothing is installed globally, and nothing is written to your Codex config until you run install-hook. Delete the cache with rm -rf ~/.npm/_npx. It is one file, small enough to read in full first.

It cannot approve anything

It registers as a Codex hook so it learns when your agent is waiting. Hooks may return a decision, and this one always declines to, twice over: it writes nothing to standard output, and it registers asynchronously, either of which alone makes Codex discard a verdict. You still approve in your own terminal.

grep -n 'stdout.write' the file: three hits, all usage printing, none in cmdHook

It reads counters, not content

Token counts, timestamps and state names. It never retains the text of your prompts, your code, or the model's replies. A test in the suite walks everything it extracts and fails if any value is a string.

npm test, then read helper/test/metrics.test.js

It has no dependencies and no network

One file, four imports, all from the Node standard library. There is no HTTP client anywhere in it, and closing the terminal ends it completely.

grep for require of http, https, net, tls, dns, or fetch

Run it in the foreground, watch it, and stop it with Ctrl-C:

npx github:sammarcus/codex-companion

# or look before you leap: what it can see, changing nothing
npx github:sammarcus/codex-companion doctor

Faces are swappable

The drawing sits behind an interface. A face receives how open the eyes should be, where the gaze is pointed, the state and a colour, and draws. It never decides when to blink, and it never touches the state machine, the transitions or the layout.

Three ship. Hold the second button for about a second to cycle them, or send one over the wire. The choice persists, so changing the look needs no reflash.

printf '{"face":"bear"}\n' > /dev/cu.usbmodem<N>

One trap, learned on hardware and worth knowing before you write your own: a half-width that computes to a non-numeric value passes every minimum check and then hands the graphics library a radius it never returns from. The board greets and then goes silent forever. Clamp the base of any exponent.

Everything the device speaks

One JSON object per line at 115200 baud. Every field is optional and the device keeps the last value it was given, so you can send one key and change one thing. That is the whole protocol, which means anything that can write to a serial port can drive this.

{"state":"waiting","ring":0.62,"center":"62%","label":"CTX","sub":"your turn"}

It answers ok per accepted line, and greets on boot with its stored name. One quirk to design around: the chip's transmit runs a message behind, so an acknowledgement usually arrives only once the next line is written. Never build a blocking handshake on it.

Built for fourteen people. One binary, one hash, no unit compiled differently from any other. Source at github.com/sammarcus/codex-companion.
