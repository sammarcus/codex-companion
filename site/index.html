Codex Desk Companion

A small creature that lives on your desk.

Plug it into anything that supplies 5V and it wakes up, blinks, looks around and settles in. That much needs no software at all. Add the optional program and it starts reporting: green means the turn finished, amber means it is waiting on you, and you can read that from across the room without switching windows.

What is on your desk

It already works.

Plug it into any USB port, any charger, any battery. No app, no account, no WiFi, no pairing, no setup. It lights up and stays lit, and that is the whole object. If you read nothing else on this page, nothing is missing.

The hardware is a LILYGO T-Display-S3: an ESP32-S3 with a 320 by 170 colour LCD and two buttons. There is no radio in use, no microphone and no camera. The only wire out of it is the USB cable you plugged in.

With nothing talking to it, it runs ambient mode forever: a face that blinks, glances around and drifts slowly through two blues and a teal, with your name under it. That is the state most of these will spend most of their life in, and it is meant to be pleasant to sit next to rather than something demanding your attention.

The five states

What the colours mean

These appear only when something on your machine is telling it what your session is doing. The one worth having is waiting.

  • idle Blue. A session is open and nothing is running. The eyes blink and look around.
  • busy Amber, breathing slowly. Your agent is working. The face squints and its gaze tracks back and forth across something only it can see.
  • waiting Amber, pulsing, with the head hopping on every beat. Your agent has asked you something and is stopped until you answer. After ten seconds the pulse turns red and doubles in speed. Press the left button and it settles to a steady amber: it knows you know.
  • done One green flash and a happy squint, then back to resting. One finished turn is exactly one flash, never a repeat.
  • sleep Dim, eyes shut, breathing on a four second cycle. Only ever reached because something asked for it.

If the machine that was talking to it goes quiet, the screen dims after thirty seconds and returns to ambient mode after five minutes. It will never sit there pulsing about a question that no longer exists.

Two lines, once

Put your name on it

The name is stored on the device itself. It survives unplugging, and it survives anything done to the firmware later. Up to 24 plain letters: anything outside plain ASCII is dropped before the name is stored, so José becomes Jos and a name with nothing plain left in it is refused outright. Write accents out. Nothing is printed back to your terminal either way, so the screen is the confirmation: your name appears on it within a second. If more than one path prints, unplug the board, run the first command again, and use the one that vanished.

# find the port the board is on
ls /dev/cu.usbmodem*

# use whichever path that printed
printf '{"name":"Your Name"}\n' > /dev/cu.usbmodemXXXX

To take it off again, send an empty one: printf '{"name":""}\n' to the same path. Nothing else about the device changes.

Optional, and genuinely optional

Make it show your live session

There is one file. You run it with Node, in a terminal, in the foreground. While it runs, the screen adds a ring for how full your context window is and a colour for what your Codex session is doing. Ctrl-C ends it completely. It is a bonus, not a requirement.

What it does

  • Reads two fields of each Codex hook event: the event name, and the path of the session file Codex is already writing.
  • Reads numbers out of that session file: token counts and turn boundaries. Every other line is skipped by a substring test before it is ever parsed.
  • Sends one short JSON line down the USB cable, at most once a second and at least every two seconds.
  • Writes one file, ~/.codex/hooks.json, and only if you run install-hook. It prints the exact bytes first.

What it never does

  • It cannot approve or deny anything. Approval prompts stay in your terminal and you answer them, exactly as you would with none of this installed.
  • No network. It never requires http, https, net, tls, dns or dgram, and never calls fetch. Grep for them. The one built-in that can run anything, child_process, is used five times: ioreg to find the board, stty to set up the line, lsof to see whether another program has the same serial port open, and node and codex with --version.
  • No background service. No launch agent, no daemon, no login item, no cron, nothing that starts itself.
  • It never reads your prompts, your code or your output. Everything that reaches the screen is a number, a timestamp, or one of five fixed words.

The whole of what goes down the wire is one line like this, and there is no traffic in the other direction beyond the board saying ok:

{"state":"waiting","ring":0.62,"center":"62%","label":"CTX","sub":"your turn"}

No tool name, no command, no file path, no model name, no session id. The screen says that you are the one holding things up. Your terminal says what for.

Running it

Node 20 or newer. macOS is the supported platform, because it finds the board by asking ioreg. Get the file, then:

node codex-companion.js doctor   # look before you leap
node codex-companion.js          # run it. Ctrl-C stops it.

doctor answers nearly every question in one screen: which serial ports it can see, which one it picked, whether the board answered, which Codex it found, and whether anything in your config.toml means approval prompts never happen (in which case the amber light can never appear, and the device will look broken while working perfectly).

If you want it to follow your session automatically

Register it with Codex's own hook system. This is the only thing here that writes a file.

# print the exact bytes, write nothing
node codex-companion.js install-hook --dry-run

# print them, then write the file
node codex-companion.js install-hook

It merges into an existing hooks.json rather than replacing it, and adds only its own entries. Codex will not run a hook it has not been told to trust, so the next time you start Codex it says Hooks need review. Approve it there, or list hooks any time with /hooks. Eight events are registered: PermissionRequest is the amber one, Stop is the green one, the tool events are busy, and the session boundaries are idle.

Uninstalling

node codex-companion.js uninstall-hook

It removes exactly what it added, leaves anything else in the file alone, and deletes the file entirely if it held nothing else. Then unplug the board. Nothing else was ever written anywhere.

Checking that yourself

Every claim above is one command away, and none of them need you to trust me:

grep -n "require(" codex-companion.js
# 4 lines: node:fs, node:path, node:os, node:child_process

grep -nE "fetch\(|XMLHttpRequest|WebSocket" codex-companion.js
grep -nE "require\((.)(node:)?(http|https|net|tls|dns|dgram)" codex-companion.js
# both silent: it has no way to reach the network

grep -niE "launchctl|launchagent|systemctl|crontab|plist|daemon" codex-companion.js
# one hit, the comment saying it installs none of those

No software required

The two buttons

Every gesture here works on a board that has never met a computer. The left button is "tell me something". The right button is the panel controls. The figures on the stats screen are the one thing that needs the optional program: with nothing ever attached they are all zero, because nothing has happened for the board to count.

GestureWhat happens
Tap leftAcknowledge a pending question, if there is one. Otherwise open the stats screen: turns, tokens, longest turn and best day, all of which the optional program feeds. Tap again for a focus timer, which needs nothing at all.
Tap rightStep the brightness, one tier per press.
Tap bothPut up a DO NOT DISTURB sign, big enough to read across an open-plan floor. Any single press takes it down.
Hold right, 0.8sChange the face. Three of them, and it remembers.
Hold left, 2sA small jumping game, for the ten minutes in the middle of a long turn. The best score is kept.
Hold both, 5sFactory reset: forget the name, the face and everything else, then play the out-of-the-box sequence again. Only while nothing on your computer is talking to it. On USB power alone that is always true, so do not unplug anything: the board needs power to hold a button for five seconds.

The right button gets you out of anything. That is the whole exit model, and it is what the on-panel legends say too. On the game, the stats screen and the focus timer the left button is that screen's own action instead: it jumps, it goes on to the timer, and it starts or pauses the clock.

Nothing here can ever cover a pending question. Every screen on this device steps aside for the amber pulse. The sign, the message card and the focus timer come back afterwards; the game and the stats screen close, because after answering a question you are back at your keyboard.

If something looks wrong

It probably is not

The screen is black

Unplug it and plug it back in without touching either button. The left button doubles as the chip's boot pin, so holding it while power arrives puts the board into flashing mode instead of starting up: black panel, nothing printed, and it will sit there. A hand gripping the top edge while pushing in a USB-C plug is holding that button. This is the one thing on the device with no rescue on the panel itself, and a replug with no buttons touched is the whole fix.

No port shows up at all

Almost always the cable. A charge-only USB-C cable powers the board perfectly and carries no data, so no port ever appears. Try another cable first, then the other USB socket on the board.

The percentage is stale

The board keeps the last value it was sent. It dims after thirty seconds of silence and goes back to its own animation after five minutes. Nothing is broken.

It never goes amber

Run doctor and read the approvals line. If your Codex config never asks for approval, there is no prompt for the device to show.

It refuses to pick a port

Two boards matched, and it will not guess between them. Name the one you want with --port /dev/cu.usbmodemXXX.

Fourteen of these exist. Every one is flashed from the byte-identical image, so the whole batch has one binary and one hash. Each unit works out its own label from the chip's MAC address, and the name on the screen is set afterwards over the cable, which is why nothing here was built per-person.
